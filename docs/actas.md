## Acuerdos

### 1. Idea elegida

Se acuerda desarrollar **LactoRuta**, una aplicación para la gestión del acopio de leche.

La idea fue seleccionada porque responde a un problema real y verificable de empresas dedicadas al acopio de leche en la zona. Actualmente, el proceso de recolección, traslado y recepción puede realizarse de forma manual o mediante información dispersa, lo que dificulta el control de las entregas, cantidades recolectadas, rutas, incidencias y datos de los productores.

Además, la propuesta cumple con los criterios obligatorios del checklist de viabilidad:

* Cuenta con una entidad principal clara para realizar las operaciones CRUD.
* Requiere autenticación de usuarios mediante inicio de sesión.
* Tiene sentido funcionar sin conexión a internet, permitiendo registrar información en zonas con conectividad limitada y sincronizarla posteriormente.
* Su alcance puede mantenerse dentro de un número realista de pantallas y entidades para desarrollarse durante el semestre.

Asimismo, se cuenta con la posibilidad de validar la aplicación con un usuario real relacionado con el proceso de acopio de leche.

### 2. Lluvia de ideas e ideas descartadas

Durante la reunión, el equipo realizó una lluvia de ideas y propuso las siguientes cinco alternativas:

1. **LactoRuta – Sistema de gestión de acopio de leche.**
   Aplicación para registrar y gestionar la recolección, traslado y recepción de leche, así como la información básica de los productores. Esta propuesta fue seleccionada porque responde a un problema real, tiene una entidad principal clara, requiere autenticación, puede funcionar sin conexión a internet y posee un alcance viable para desarrollarse durante el semestre.

2. **StockLocal – Sistema de inventario y ventas para pequeños negocios.**
   Aplicación para controlar productos, existencias, ventas y movimientos de inventario en bodegas o pequeños comercios. Fue descartada porque es una propuesta muy común y el equipo no contaba inicialmente con un negocio específico que permitiera validar directamente la solución con un usuario real.

3. **CanchaFácil – Sistema de reserva de canchas deportivas.**
   Aplicación para consultar horarios disponibles y realizar reservas de canchas deportivas. Fue descartada porque requería definir aspectos adicionales, como disponibilidad en tiempo real, gestión de horarios y posibles conflictos entre reservas, lo que podía ampliar innecesariamente el alcance inicial del proyecto.

4. **UniControl – Sistema de control de asistencia y actividades estudiantiles.**
   Aplicación para registrar la asistencia de estudiantes y gestionar actividades o eventos. Fue descartada porque requería definir permisos y reglas para diferentes tipos de usuarios y no se contaba con una institución específica para realizar la validación inicial del sistema.

5. **AgroPedidos – Sistema de pedidos y entregas de productos agrícolas.**
   Aplicación para registrar pedidos, productos, clientes y entregas de pequeños productores. Fue descartada debido a que, para cubrir adecuadamente el proceso, podía requerir varias entidades y funcionalidades adicionales relacionadas con inventario, pedidos y distribución, aumentando el alcance del proyecto.

Después de evaluar las propuestas mediante el checklist de viabilidad, el equipo determinó que **LactoRuta** era la alternativa más adecuada, ya que presenta un problema concreto, permite definir claramente las funcionalidades principales y puede validarse con un usuario real. Asimismo, el funcionamiento sin conexión representa una característica útil para el contexto en el que se realizaría el proceso de recolección.
